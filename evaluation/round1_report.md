### 평가의 한계
- **회의록 평가셋이 5건(할 일 22개)뿐이다.** 1건이 지표를 약 5%p 움직인다. README 5.1절 계획(15~20건)까지 늘려야 한다.
- **Agent와 채점기가 같은 모델이다.** 채점기 점검(일부러 틀린 기록 5건 모두 실패로 판정)으로 관대하지 않음은 확인했고, 판정 근거 일부를 직접 열어 실제 기록과 맞는지 확인했다.
- **인-아웃 기대 특성이 느슨한 곳이 있다.** 1번 "할 일 8건 내외"는 추출 누락 1건을 잡지 못했다. 할 일 단위 정답 비교(기능 지표)가 함께 필요하다.
- **LLM 결과는 실행마다 조금씩 다를 수 있다.** 1차는 각 평가를 1회만 실행했다.

## 5. 2차 평가까지 개선 계획
1. **장애 대응 (xfail 6건 해소)**
   - Toolbox에 타임아웃과 재시도를 넣는다
   - Resolver·Context의 도구 오류를 경고로 바꿔, 한 도구가 실패해도 검토 표까지 가게 한다
2. **기한의 과거 맥락 연결**: "운영 이전 리허설 전까지"처럼 기준 일정이 과거·이전 회의록에만 있을 때 `reference_date`를 찾아 넘긴다
3. **추출 누락**: 진행 보고 형태의 할 일("~까지 마무리하겠다고 함") 추출 예시를 Extractor에 추가한다
4. **RAG 품질**
   - 결정 충돌 경고를 출처가 들어간 문장형으로 바꾼다
   - Action Items 표 분할과 질의 확장을 Hit@k로 비교한 뒤 RAGAS를 다시 잰다
5. **2차 평가**: 1차와 같은 명령으로 인-아웃, 기능 지표, RAGAS, 장애 주입을 다시 실행하고 [round2_report.md](round2_report.md)에 비교한다
